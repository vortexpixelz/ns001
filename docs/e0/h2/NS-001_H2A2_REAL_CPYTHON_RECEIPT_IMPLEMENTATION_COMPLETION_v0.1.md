## Closed integration gaps

**Transcript integration — CLOSED offline.** Ordered channel chunks retain every
submitted byte, including invalid/interrupted input. Commands, stdout and stderr
remain separate, with original byte offsets/counts and arrival sequence. One outstanding
monotonic token must match one complete result; async stops bind to the outstanding
execution command independently of whether the result precedes or follows the stop.
Inferior/thread notifications bind the actual MI PID/TID to retained custody. Raw
register-name/value and explicit memory results build the caller/receiver snapshots;
missing, duplicate, partial, ambiguous, cross-token or unrelated records fail closed.
Expected trap classification and separately submitted observed native trap captures
must both match; a PC or bare end-stepping-range record alone cannot qualify receipt.
Unqualified software-breakpoint, policy or diagnostic evidence prevents acceptance.

Q1 readbacks extract actual scalar values using independently frozen output-format
descriptors. Every auto-load boolean facility is checked separately. All 26 settings,
stopping/register-control permissions, observer-off state and early ordering must match.
The fixture output dialect is explicitly synthetic; no statement is made that these
format fixtures were measured from a launched installed GDB. A later real admission
must independently freeze the actual pinned tool's readback/trap/log formats.

**Preparation/lifecycle — CLOSED offline.** Qualification/artifact/build/interface/
origin bytes are hash-addressed before reservation and registration. PREPARED requires
protected A, single bounded derivation/resize/RET association, exact engine and callable,
decoded READY roots/source, custody/bootstrap/guard descriptors, actual MI readbacks,
hardware/control/death-chain evidence and complete text-range measurement descriptors.
There is no supplied ready/accept flag that can bypass those predicates. Precondition
failure records one frozen primary refusal without creating ATTEMPTED or an entry.
ATTEMPTED append, file/directory synchronization and exact journal readback precede
the attempt object's one-use observation authority. An observer cannot create/backfill
ATTEMPTED or resume a reconstructed nonterminal attempt; recovery is the available path.
Normal observation builds its witness from raw measurements; an optional conflicting
caller-supplied witness is refused. Unknown/unrepresentable facts remain null or cause
ABORTED, including unsupported counts. Actual invalid keyword strings are preserved
when representable. No expected name/value is copied into a failed observation.

**Reserved-only recovery — CLOSED offline.** Reserve-only and registration are distinct.
Recovery retains the original reservation and ledger, creates no request or registration,
records absent hashes as null, and produces deterministic separate ABORTED evidence.
Repeat matching recovery is idempotent; conflict/torn recovery stops without overwrite.
Recovered attempts cannot register/prepare/dispatch. Monotonic IDs are not reused;
lost/conflicting reservation or store custody blocks continued reservation. Partial
records remain visible and hash-bound. Recovery packaging never dispatches.

**Repetition/determinism — CLOSED offline.** Comparison requires fresh distinct IDs
and independently verified complete positive packages. It validates originals and
compares E, request, registration, events, witness and all four source captures.
It removes only attempt_id, event predecessor/witness hashes and the dispatch's
ATTEMPTED-event hash. Engine/artifact/fixture hashes, arguments, outcomes, counts,
case IDs, violations and substantive measurements remain. Original records and raw
forensic volatility remain retained and unchanged; no forensic record is rewritten
to manufacture canonical identity. Identical full inputs serialize deterministically.
Positive repetition passes; same ID, changed case and altered captures fail.

**Evidence/package writer — CLOSED offline.** The enforced successful order is
complete capture/confirmed-death evidence, synchronized observer files, capture
manifest, synchronized witness, durable terminal, package manifest, external sidecar,
then read-only completeness/hash verification. Raw MI/setup streams, order, maps,
derivation, stops/native traps, arguments, protected byte captures and completion
are retained with the hash-addressed dossier and original records. Per-attempt store/
custody/lock/reservation-ledger snapshots prevent a later reservation changing an
earlier package's identity. Every actually retained attempt fragment is inventoried.
Manifests exclude themselves; the package includes the capture manifest and uses
an external digest sidecar without recursive hashes. Public ACCEPT requires the
full fixed inventory, original request/registration/E/journal/witness links, byte
captures and exact manifest lengths/hashes. Terminal-write packaging authority is
consumed once before package writes. An interrupted package cannot be resumed or
automatically filled into success by a reconstructed writer. Existing valid terminals
remain byte-identical even when later packaging is incomplete; verification stays false.

**Custody/bootstrap/guards — CLOSED offline.** Validation binds the retained namespace,
exclusive store, artifact pins, bootstrap root/parameter/read/no-retry/death policy,
parent/credential/channel chain, exact engine/tool descriptors and Q1 descriptor.
Actual guard state is separate from pinned policy: source/path/execution operations
produce the existing refusal codes, with EXECUTION_PROHIBITED invalidating acceptance
regardless of which earlier code is primary. Missing, wrongly typed or conflicting
evidence cannot masquerade as absence of operations or a completed native admission.

All canonical schemas/key sets and the frozen refusal order are preserved. No new
serialized OBSERVED state, refusal enum or surrogate receipt fallback was introduced.
